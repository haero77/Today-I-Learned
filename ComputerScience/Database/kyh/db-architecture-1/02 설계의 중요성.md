# 6. 데이터베이스 설계의 첫걸음

## 설계를 왜 배워야할까?

> 👉 **설계를 배우지 않으면 잘못된 설계를 하게되어 기술 부채가 되고, 결국에는 고객 이탈을 야기하며 비즈니스를 망치게됨.**
> 
> 👉 *잘못된 설계는 데이터 무결성 훼손, 막대한 유지보수(간단한 기능인데 수십 개 파일 수정) 비용의 야기, 성능 저하 & 고객 이탈로 이어져 비즈니스를 망침. 따라서 시간을 투자하여 반드시 배울 필요가 있음.

- '일단 만들고 보자'는 생각으로 주먹구구식으로 테이블을 만들다 보면, 처음에는 빠르게 개발되는 것처럼 느껴질 수 있으나, 서비스가 커지고 데이터가 복잡해질수록 문제는 눈덩이처럼 불어남.
  - 문제 예시
    - 데이터가 중복 저장되어 서로 맞지 않음
    - 간단한 기능을 하나 추가하기 위해 수십 개의 파일을 수정해야함.
    - 무엇 보다 애플리케이션의 속도가 점점 느려져 **사용자들이 떠나가는 '재앙'을 맞이함.**
- **이처럼 설계 없이 진행된 개발은 시간이 지날수록 '기술 부채(Technical Debt)'로 이어짐.**

## 강의 흐름

> 👉 설계의 중요성과 재앙 -> 설계 3단계 로드맵 -> 개념적/논리적 모델링 -> 정규화 -> 물리적 모델링

1. **설계의 중요성**: 먼저 설계가 왜 중요한지, 잘못된 설계가 어떤 재앙을 불러오는지 현실적인 사례를 통해 체감.
2. **설계의 3단계 로드맵**: 아이디어를 실제 데이터베이스로 만들어가는 전체 과정(개념적 설계 -> 논리적 설계 -> 물리적 설계)의 큰 그림을 이해.
3. **개념적/논리적 모델링**: 요구 사항을 분석해서 핵심 데이터를 찾아내고(엔티티), 그 데이터들이 가지는 속성을 정의하며, 데이터들 간의 관계를 명확하게 표현하는 방법을 학습. ERD(Entity-Relationship Diagram) 작성법, 다양한 키(Key)의 종류와 역할, 관계의 종류(1:N, M:N 등)와 식별 및 비식별 관계 등을 깊이 있게 다룸.
4. **정규화**: 데이터의 중복을 제거하고 무결성을 높여 모델의 품질을 한 단계 끌어올리는 '정규화' 과정을 학습.
5. **물리적 모델링**: 최종적으로 완성된 논리 모델을 실제 MySQL 데이터베이스에 최적화된 테이블로 만드는 방법 학습.

## 실습 프로젝트 쇼핑몰의 초기 요구사항

- 이번 강의는 우리가 직접 가상의 쇼핑몰을 만들고, 이 쇼핑몰의 데이터베이스를 설계하고 만들어가는 과정을 함께함.
- **초기 요구 사항**
  - 회원이 가입하고 자신의 정보를 관리할 수 있다.
  - 판매자는 상품을 등록하고 관리할 수 있다.
  - 회원은 상품을 주문할 수 있다.
- **백문이 불여일타**: 반드시 직접 실행 필요. 백번 보는 것 보다 한번 실행하는 것이 더 확실히 배울 수 있음.

## 데이터베이스가 가장 중요 ⭐️️️⭐️️️⭐️️️

- 실무 개발에서 가장 중요한 것 하나만 선택하라고 한다면, 나는 주저 없이 데이터베이스 설계를 선택할 것임. 그만큼 데이터베이스가 중요함.
  - 실무에서 발생하는 장애의 90%는 데이터베이스를 잘못 다루어 발생.
  - Java, Python 등 애플리케이션 코드는 비교적 수정이 쉬움. 
    - But, 잘못된 데이터베이스 설계는 수정이 매우 어려움. 몇 달을 고쳐도 해결이 안 될 수 있음.
  - **_잘못된 설계는 성능 저하, 데이터 불일치, 유지보수 어려움(수십개 파일 수정)이라는 기술 부채로 돌아오지만, 잘된 설계는 어떤 비즈니스 요구사항 변화에도 유연하게 대처할 수 있는 튼튼한 기반이 되어줌._**
- 데이터베이스는 백엔드 개발자 역량의 50%를 차지함.
  - 데이터베이스에 대한 깊이있는 이해가 나의 핵심 성장 비결임.
  - JPA 같은 책을 저술할 수 있었던 이유도 데이터베이스를 잘 이해한 덕분임.
- 좋은 애플리케이션의 **근간은 좋은 데이터베이스 설계**에서 나온다.
- 설계는 프로젝트를 주도하고, 좋은 시니어로 성장하기 위한 **필수 역량**이다.
  - 설계 능력이 없으면 중요한 신규 프로젝트를 주도할 수 없다.
