# toc-fill

## 개요

인덱스 파일(README.md 등)에 `- [섹션명](./파일.md)` 형태의 항목이 있을 때, 연결된 파일의 `#` 헤딩을 읽어 하위 링크를 자동으로 채운다.

## 인자

```
/toc-fill <index-file> <linked-md-file>
```

- `index-file`: 채울 대상 인덱스 파일 (예: `Careers/jemini-resume/README.md`)
- `linked-md-file`: 헤딩을 추출할 마크다운 파일 (예: `Careers/jemini-resume/02 하지 말아야할 것.md`)

## 워크플로우

### 1. 헤딩 추출

`linked-md-file`에서 `#` 헤딩을 모두 추출한다.

```bash
grep -n "^#" "<linked-md-file>"
```

`#` 헤딩만 추출한다 (`##`는 제외). 즉 `^# ` 패턴으로 필터링한다.

### 2. 앵커 슬러그 생성

각 헤딩 텍스트를 앵커 링크로 변환한다.

변환 규칙:
1. 앞의 `# ` 제거
2. 영문 소문자로 변환
3. 특수문자 제거: `. ! ? , ' " ( ) * _`
4. 공백 → `-`
5. 연속 하이픈 → 단일 `-`
6. 앞뒤 `-` 제거

예시:
- `# 5. 누구나 다 아는 템플릿 쓰지 마세요` → `5-누구나-다-아는-템플릿-쓰지-마세요`
- `# 14. 관리 안 된 깃허브, 블로그 적지 마세요.` → `14-관리-안-된-깃허브-블로그-적지-마세요`
- `# 17. 절대! 절대! 회사의 코드나 기밀 사항을 쓰지 마세요` → `17-절대-절대-회사의-코드나-기밀-사항을-쓰지-마세요`

### 3. 파일 경로 인코딩

`linked-md-file`의 파일명을 URL 인코딩한다 (공백 → `%20`).

예: `02 하지 말아야할 것.md` → `02%20하지%20말아야할%20것.md`

상대 경로는 `index-file` 기준으로 계산한다.

### 4. 하위 링크 생성

각 헤딩에 대해 아래 형식으로 하위 링크를 만든다:

```
  - [헤딩 텍스트](./<인코딩된-파일명>#<앵커-슬러그>)
```

### 5. index-file 업데이트

`index-file`에서 `linked-md-file`에 연결된 부모 항목을 찾아, 기존 하위 항목을 새로 생성한 목록으로 교체한다.

- 부모 항목 다음 줄에 들여쓰기 2칸으로 삽입
- 기존 하위 항목이 있으면 교체, 없으면 추가
- 다음 최상위 항목(들여쓰기 없는 `-`)이 나오면 삽입 종료

## 실행 예시

```
/toc-fill Careers/jemini-resume/README.md "Careers/jemini-resume/02 하지 말아야할 것.md"
```

실행 결과 — `README.md`의 해당 항목 하위가 채워짐:

```markdown
- [02 하지 말아야할 것](./02%20하지%20말아야할%20것.md)
  - [5. 누구나 다 아는 템플릿 쓰지 마세요](./02%20하지%20말아야할%20것.md#5-누구나-다-아는-템플릿-쓰지-마세요)
  - [6. 너무 많이 축약하지 마세요](./02%20하지%20말아야할%20것.md#6-너무-많이-축약하지-마세요)
  - ...
```

## 주의사항

- `##` 이하 헤딩은 하위 링크에 포함하지 않는다 (`#` 레벨만).
- 파일에 한글이 포함된 경우 공백만 `%20`으로 인코딩하고 한글은 그대로 유지한다.
- 실행 전 현재 파일 내용을 Read로 확인하고, 변경 후 결과를 사용자에게 보여준다.
