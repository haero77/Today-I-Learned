# 1. 강의 소개

## 강의 소개와 검토자 입장에서 바라본 채용

- TO 한 자리에 400명 이상 지원.
- 회사에서는 어떤 지원자를 뽑을까?
  - 회사에 와서 기여할 사람.
  - 결국 이직할 확률이 낮은, 오래다닐 지원자를 어떻게 판별할지 가 중요.

### 이직할 확률이 낮은 지원자를 어떻게 판별할 수 있을까?

- 지원 허들과도 관련.
  - 원클릭 플랫폼은 지원 허들이 낮음.
- 어떤 회사는 JD에 업무를 자세히 써놓는 방식으로 허들을 높임.

## 최근에 보이는 개발자 이력서 작성 프로세스의 문제점

- 구글링 > 잘 쓴 이력서 보고 템플릿 이식 > 이력서 작성, 완성 > 지인 피드백 > 서류 제출 > 서류 합격/탈락
  - 이 잘 쓴 이력서보고 이식하는 과정에서 오류를 범함.

### 잘 쓴 이력서란?

- 서류검토자 입장에서 **읽기 좋은 이력서.**
  - 직관적, 명료함. 가독성 좋음.
- (⭐️ 가장 중요) **지원 공고와 핏한 이력서** (필수 역량, 우대 역량)
  - JD에 필수/우대 역량이랑 관계없이 연차만 쌓이면 지원 난사하는 경우가 많음 😅

### 왜 잘 쓴 이력서를 따라했는데 내 이력서는 밋밋하지?

1. 잘 쓴 이력서인 그들의 경험과 우리의 경험이 다름.
2. 밋밋한 이유는, 대부분의 경우 내가 한 것이 없어서가 아니라, **_👉 핵심을 강조하지 못하기 때문._**
3. 나를 얼마나 잘 아는지 **메타인지**가 가장 중요한 요소 ⭐️
4. 결과에 집중하기 보다는 어떤 경험에서 어떤 문장이 나왔는지 **과정**을 들여다 보는 것이 필요.

# 2. 이력서 작성 전, 갖춰야할 마인드셋

> - 이력서를 작성하면서 자신감을 잃어가는 경우
> - 급하게 이력서를 쓰려고 하는 경우 -> 퀄리티 하락
> - 타인과 끊임없이 비교하며 자신을 갉아 먹음
> - 앞으로 이력서를 작서앟면서 꼭 가졌으면 하는 마인드를 이번 섹션에서 소개.

## 강인한 정신에 강인한 이력서가 깃든다

### 이력서를 완성하는 결과에 집중하는 것이 아니라, 작성 과정에 집중하자

- 결과물만 보면 디테일을 놓친다.
- 단순 완성보다는, 이력서를 작성하는 과정에서 이력서 작성 스킬이 쌓인다. 이걸 얻어가는 것이 포인트

### 타인과의 상대적인 비교로 자신감을 잃지 말기

- 나보다 잘하는 사람은 항상 존재한다.
  - 이 자신감 부족은 이력서에도, 면접에도 드러난다.
- 비교의 대상은 타인이 아닌 자기 자신으로 설정한다.
  - 하루 전의 나, 일주일 전의 나, 한 달 전의, 일년 전의 나!
  - 잘하는 사람을 보고 꿇릴 필요없고, 그들의 노력을 존중한다!
- 가치 없는 경험은 없다. 
  - 이 경험이 다음 경험을 위한 도약이다.
  - 본인이 모르는 사이에 엄청난 경험이 쌓여있을지도?

### 이력서는 빨리 쓸 수가 없다.

- 왜? 완벽하게 쓰려고 하니까.
  - 과정 생략하고 '잘' 쓰려고만 하면 답답함이 느껴진다.
  - 처음부터 **천천히** 써보자.
- 자신이 뭘했는지 정확히 파악해야 이력서 작성이 가능
- 메타인지의 중요성
  - 자기 인식, 자기 평가, 조절과 수정, 자기 모니터링(과장은 줄이고, 자랑은 효과적으로).

# 4. 합격률의 진실, 합격률 체크

- 390개 기업에 채용 플랫폼으로 지원 -> 합격률 4.3% (검토자입장에서 신뢰도 하락)

  - 지원서에 구체적인 지원동기까지 있다면..?

## 어떤 이력서가 눈길이 갈까?

- 어떤 사람을 뽑을까?
- 눈길이 가는 이력서?
- 마음을 움직이는 이력서!

## 마음을 움직이는 이력서가 뭘까?

- 대부분, 어디에나 지원할 수 있는 마스터 이력서를 제출.
- 제네럭하지 않은 이력서, 우리 회사에 지원하려고 작성한 이력서.
  - 지원 동기를 잘 작성하면 마음을 움직일 수 있음.
- 우리 회사에 진짜 오고 싶어하는 지원자의 지원동기가 있다면 그 간절함이 느껴지기 마련
- 개인화 서비스는 왜 하는 걸까? -> 마음을 움직여서 (내 이력서에) 오랜 시간 머물게 하는것

# 5. 서류 탈락하는 이력서 안티패턴

## 사소하지만 이력서 퀄리티를 낮추는 행동

- 하이어링크 안 달고 링크 그대로 붙여넣는 경우.
- 저근 불가능한, 만료된 URL
- PDF의 경우 A4 사이즈가 아닌 커스텀해서 사이즈가 다른 이력서.
  - 한 페이지에 연관있는 내용을 다 넣으려해서 발생.
  - 출력 하는 경우도 있고, 전 세계적으로 표준 사이즈.
- 정돈 되지 않은 이력서 -> 폰트(궁서체), 줄 간격, 자간, 표 여백 등
- 너무 긴 이력서(10장도 넘어가는 경우 있음)
  - 프로젝트 하나 하나 마다 너무 디테일 한 경우 (뭘 빼야할지 모름)
  - 서류 검토자가 궁금한 것은 기술 역량과 극복한 경험
    - 근데 이걸 왜 했고, 어떤 아이디어이고, 어떻게 구현했는 것 까지 서사를 다 적는 경우도 있음.

## 퇴색된 Github 잔디

- GitHub에 잔디를 억지로 심는 지원자
- 꾸준함은 성장에 있어서 뗄레야 뗄 수 없는 정말 중요한 능력.
- 커밋 어뷰징 -> 커밋 날짜 변경, 연속적인 리드미 수정, 커밋 배치.
- 꾸준히 뭔가를 하기 위해 -> 잔디를 하루도 빠짐없이 심었다 -> 이 과정에서 어떤 성과나 결과를 얻었다
  - 여기까지 나와야 신뢰도가 올라간다.

## 목적을 잃어버린 수치화

### 객관적이지 않은 수치화 

- 최근 이력서에서 수치화를 많이 시도하고 있음 
- 검토자 입장에서 "사용자가 200% 증가했습니다"를 본다면?
  - 몇 명에서 몇 명으로 증가되었는지 알 수가 없음 
  - 1명에서 2명으로 증가해도 200% 증가..!
- 객관적인 수치의 부재 
- 모조건적으로 수치화하려고 해서 발생하는 문제. 왜 수치화하는지를 생각해보자

### 수치화 개선 예시

## 이력서랑 포트폴리오는 따로 준비

- **_이력서와 포폴을 따로 준비하는 것을 권장._** 역할이 다름.
- 이력서는 요약본.
  - 세세한 내용이 궁금하거나 확인이 필요하면 포트폴리오로 접근.
- 포트폴리오
  - 왜 했고 뭘 했는가? -> 구체적인 문제 해결 과정, 트러블 슈팅
    - 이력서에 적지 못했던 부분을 디테일하게 풀어나가는 공간.
  - 무작정 장확하게 적지말기
  - 간결함, 직관적, 가독성 = 이력서와 룰은 같음.
  - 이력서는 내 경험이 요약되어있는 압축본.
  - 디테일하게적기 != 길게 적기
