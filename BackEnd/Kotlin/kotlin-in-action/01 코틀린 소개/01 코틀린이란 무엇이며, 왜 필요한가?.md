# 코틀린

- 코틀린: JVM 플랫폼과 JVM 외의 다른 플랫폼에서 돌아가는 현대 프로그래밍 언어
- 코틀린은 범용 언어. 간결하고 안전 & 실용적

# 1.1 코틀린 맛보기

```kotlin
data class Person( // 데이터 클래스
  val name: String, // 읽기 전용 프로ㅌ퍼티
  val age: Int? = null // 널이 될 수 있는 타입과 파라미터 기본값
)

fun main() { // 최상위 함수
  val persons = listOf(
    Person("영희", age = 29), // 이름 붙은 파라미터
    Person("철수"),  // 트레일링 콤마
  )

  val oldest = persons.maxBy {  // 람다식
    it.age ?: 0 // 엘비스 연산자
  }
  println("가장 나이가 많은 사람: $oldest") // 문자열 템플릿
  // 가장 나이가 많은 사람: Person(name=영희, age=29)
}
```

# 1.2 코틀린 주요 특성

- 다중 패러다임 언어.
- 정적 타입 지정(statically typed) 언어 👉실행 시점이 아닌 컴파일 시점에 많은 오류를 잡아낼 수 잇음.
- 객체지향 언어와 함수형 언어의 아이디어 조합 -> 우아한 코드 작성과 강력한 추상화를 사용할 수 있게 해줌.
- 수많은 여러 개발 분야에서 주용한 비동기 코드를 작성할 수 있는 강력한 방법 지원.

## 1.2.1 코틀린 용례: 안드로이드, 서버, 자바가 실행되는 모든 곳, 그 외의 용도

## 1.2.2 정적 타입 지정으로 인해 코틀린 성능, 신뢰성, 유지 보수성이 좋아진다.

- 정적 타입 언어의 장점: 프로그램의 모든 식의 타입을 컴파일 시점에 알 수 있음.
- 코틀린 정적 타입 언어이지만, 타입 추론이 가능하여 개발자가 타입을 명시적으로 지정할 필요가 없음.
  - 간결한 코드 작성 가능

## 1.2.3 함수형 프로그래밍과 객체지향 프로그래밍의 조합이 코틀린을 안전하고 유연하게 한다

### 함수형 프로그래밍 핵심 개념

- 일급 시민(first class) 함수: 
  - 함수를 일반값처럼 취급 가능. 함수를 변수에 저장 가능. 
  - 함수를 인자로 다른 함수에 전달 가능. 함수에서 새로운 함수 만들어 반환 가능
- 불변성
  - 함수형 프로그래밍에서는 일단 만들어지고 나면 내부 상태가 절대로 바뀌지 않는 불변 객체를 사용해 프로그램을 작성
- 부수 효과(side effect) 없음
  - 함수형 프로그래밍에서는 입력이 같으면 같은 출력을 내놓음. & 다른 객체의 상태를 변경하지 않으며 함수 외부나 다른 바깥 환경과 상호 작용하지 않는 순수 함수 사용.
  - 그 결과 같은 명령형 프로그램보다 간결하고 우아. 변수의 값을 변경하고 루프나 조건 분기에 의존하는 대신 순수 함수를 값처럼 활용할 수 있으면 더 강력한 추상화 가능.

---

### 함수형 프로그래밍 장점 3가지 (중복 제거, 안전한 동시성, 테스트 용이성)

1. 함수형 프로그래밍 사용하여 코드 중복 제거 가능. 
   1. 비슷한 작업을 구현하는 코드 조각이 있는데 세부 사항이 차이 난다면 쉽게 공통 로직을 따로 함수로 뽑고, 서로 다른 세부 사항을 인자로 전달 가능.(인자 자체가 함수)
2. 안전한 동시성
   1. 다중 스레드 프로그램 -> 같은 데이터를 여러 스레드가 변경하는 경우 많은 문제 발생. 복잡한 동기화 방법 필요.
   2. 불변 데이터 구조와 순수 함수 사용할 경우 안전하지 않은 데이터는 변경이 발생하지 않음을 보장 가능 -> 복잡한 동기화 방법 적용 불필요.
3. 테스트하기 쉬움
   1. 부수 효과가 없는 함수는 그 함수가 의존하는 전체 환경 구축 불필요. 독립적으로 테스트 가능
   2. 더 큰 복잡한 시스템을 염두하지 않고 코드의 동작을 검증 가능.

---

## 1.2.4 코루틴을 쓰면 동시성, 비동기 코드를 자연스럽고 구조적으로 사용할 수 있다

### 코루틴

> 코루틴: 스레드를 효율적으로 재활용하면서도, 개발자가 읽기 쉬운 비동기 코드를 짜게 해주는 도구

- 동시성과 비동기 프로그래밍의 문제를 코루틴이라 불리는 일시 중단 가능한 계산(suspendable computation)을 사용해 접근.
- 코루틴에서는 코드가 자신의 실행을 잠시 중단시킬 수 있고, 나중에 작업을 계속 수행 가능.


```kotlin
// 3가지 네트워크 호출을 처리하는 processUser 함수
// 순차적 실행
suspend fun processUser(credentials: Credentials): User {
  // 1. 인증 시도 (네트워크 통신)
  // 여기서 '중단' 발생! 하지만 이 함수를 실행하던 스레드는 다른 일을 하러 떠날 수 있음.
  val user = authenticate(credentials)

  // 2. 인증이 완료되면 다시 이 지점으로 돌아와 다음 줄 실행
  val data = loadUserData(user)

  // 3. 데이터를 다 불러올 때까지 또 중단 가능
  val profilePicture = loadImage(data.imageID)

  return user
}
```

- 네트워크 무한정 호출은 길어질 수 있음.
- 그러나 이 코드가 실행되는 스레드는 블록되지 않음.
- processUser 의 결과를 기다리는 동안, 스레드는 사용자 입력에 반응하는 등의 다른 작업 수행 가능

### async

```kotlin
// 병렬 실행
suspend fun loadAndOverlay(first: String, second: String): Image = 
  courtineScope {
    // 새 코루틴으로 첫 번째 이미지 적재 시작
    val firstDeferred = async { loadImage(first) }
    // 또 다른 코루틴으로 두 번째 이미지 적재 시작
    val secondDeferred = async { loadImage(second) }
    // 두 이미지가 모두 적재되면, 두 이미지를 겹친 결과 이미지를 반환
    combineImages(firstDeferred.await(), secondDeferred.await())
  }
```

# 1.4 코틀린의 철학

## 1.4.1 코틀린은 실용적인 언어다

- 실용적: 실제 문제를 해결하기 위해 만들어진 실용적인 언어.
  - 대규모 시스템을 개발해본 다년간의 IT 업계 경험을 바탕으로 만들어짐.
- 코틀린은 연구를 위한 언어가 아님.
  - 다른 프로그래밍 언어가 채택한 이미 성공적으로 검증된 해법과 기능에 의존.
  - 그 결과 복잡도가 줄어듦. 기존 개념을 통해 코틀린을 더 쉽게 학습 가능.

## 1.4.2 코틀린은 간결하다

- 코드 작성 시간보다 읽는 시간이 더 길다
- 버그 발생 시 수정할 부분을 찾기 위해서 엄청난 양의 코드를 읽어야함.
  - 관련된 코드를 모두 일고 나서야 코드를 제대로 수정 가능.
- 좋은 설계와 읽기 쉬운 네이밍도 중요하지만, 언어 자체가 간결한 것도 중요.
- 코틀린 표준 라이브러리 사용해서 반복되거나 길어질 수 있는 코드를 라이브러리 함수 호출로 대치 가능.
- 간결하면 코드 작성 시간도 줄고, 더 중요한 읽는 시간도 줄어든다. 결국 원하는 일을 더 빠르게 할 수 있게 해준다.

## 1.4.3 코틀린은 안전하다

- 안전하다: 프로그램에서 발생할 수 있는 일부 오류 유형을, 프로그램 설계 자체가 원천적으로 차단.

## 1.4.4 코틀린은 상호운용성이 좋다

# 1.5 코틀린 도구 사용

## 1.5.2 코틀린 코드 컴파일

### 코틀린/JVM에서의 컴파일 과정

- .kt 파일 -> 컴파일 -> .class 파일 생성. -> JVM에서 실행
- 코틀린 내장 클래스와 API는 의존 관계로, 코틀린 런타임 라이브러리라는 추가 정보 필요.
  - 커맨드라인에서 코드 컴파일할 때는 명시적으로 -include-runtime 옵션을 사용하여 런타임 라이브러리를 포함해야 함.
