# 01 코틀린에서 변수를 다루는 방법

## 1. 변수 선언 키워드 var Vs. val

```kotlin
var number1 = 10L // 수정 가능(Variable)
val number2 = 10L // 수정 불가(Value)
```

- 코틀린에서는 모든 변수에 수정 가능 여부(var/val) 명시 필요.

### 초기값 지정해주지 않는 경우?

```kotlin
var number1: Long
println(number1) // 오류 발생
```

### val 컬렉션에는 엘리먼트를 추가할 수 있다

### TIP: 모든 변수는 우선 val로 선언하고 필요할 때만 var로

## 2. Kotlin에서의 Primitive Type

```kotlin
var number1 = 10L
var number3 = 1_000L
```

```java
// 변환된 자바 코드
long number1 = 10L;
long number3 = 1000L;
```

- 프로그래머가 boxing/unboxing을 신경쓰지 않아도 되도록 Kotlin이 알아서 처리

## 3. Kotlin에서의 nullable 변수

```kotlin
var number3: Long? = 1_000L
number3 = null
```

- 기본적으로 모든 변수에 null 할당 불가능.
- null이 변수에 들어갈 수 있다면 `타입?` 을 사용해야함.

## 4. 객체 인스턴스화

```kotlin
val person = Person("haero77")
```

- 객체 인스턴스화 시에 new 키워드 사용 안 함

## 요약

- 모든 변수는 var / val을 붙여 주어야 한다.
    - var : 변경 가능하다 / val : 변경 불가능하다 (read-only)
- 타입을 명시적으로 작성하지 않아도, 타입이 추론된다.
- Primitive Type과 Reference Type을 구분하지 않아도 된다.
- Null이 들어갈 수 있는 변수는 타입 뒤에 `?`를 붙여주어야 한다.
    - 아예 다른 타입으로 간주된다.
- 객체를 인스턴스화 할 때 new를 붙이지 않아야 한다.

# 02 코틀린에서 null을 다루는 방법

1. 코틀린에서의 null 체크
2. Safe Call 과 Elvis 연산자
3. 널 아님 단언!!
4. 플랫폼 타입

## 1. 코틀린에서의 null 체크

### 안전하지 않은 자바 코드

```java
public boolean startsWithA(String str) {
    return str.startsWith("A");
}
```

- str이 null일 경우 NPE 발생

## 2. Safe Call 과 Elvis 연산자

```kotlin
val str: String? = "ABC"
str.length // 불가능
str?.length // 가능 (Safe Call)
```

- `?.`: 앞에 있는 값이 널이 아니면 뒤의 코드 실행.
  - str이 null 이면 전체가 null이 됨.(`str?.length` 가 null)


```kotlin
var str: String? = null
println(str?.length ?: 0)
```
- `?:` : Elvis 연산자
  - 앞에 있는 값이 null 이면 뒤의 값을 사용.
  - e.g. str이 null 이면 0을 출력.

### 코틀린 스타일의 null 체크

```kotlin
fun startsWithA1(str: String?): Boolean {
    return str?.startsWith("A")
        ?: throw IllegalArgumentException("str is null")
}

fun startsWithA2(str: String?): Boolean? {
    return str?.startsWith("A") // 앞에 변수가 null이면 null(Boolean?) 반환
}

fun startsWithA3(str: String?): Boolean {
    return str?.startsWith("A") ?:  false // 앞에 변수가 null이면 false(Boolean) 반환
}

fun calculate(number: Long?): Long {
    number ?: return 0 // number가 null이면 0 반환
    // 다음 로직
} 
```

## 3. 널 아님 단언!!

- nullable type이지만 아무리 생각해도 null이 될 수 없는 경우

```kotlin
fun startsWithA4(str: String?): Boolean {
    return str!!.startsWith("A")
}
```

## 4. 플랫폼 타입: Kotlin에서 Java 코드를 가져다 사용할 때 어떻게 될까?

```java
public class Person {
    private final String name;

    public Person(final String name) {
        this.name = name;
    }

    @Nullable
    public String getName() {
        return name;
    }
}
```

```kotlin
fun main() {
    val person = Person("Allice")
    startWithA(person.name) // person.name이 nullable하므로 에러 발생. 
}

fun startWithA(str: String): Boolean {
    return str.startsWith("A")
}
```

- null에 관련된 애노테이션 활용하면 코틀린에서 인식해서 컴파일 에러 가능.
- 그런데 @Nullable 애노테이션이 없으면 어떻게 될까?
  - 👉코틀린에서는 이 값이 nullable 인지, non-nullable인지 알 수 없음 
    - 👉 런타임에서 Exception 발생 가능.
- **플랫폼 타입이란?**
  - 코틀린이 null 관련 정보를 알 수 없는 타입.
  - 런타임에서 Exception 발생 가능.

## 요약

- 코틀린에서 null이 들어갈 수 있는 타입은 완전히 다르게 간주된다
  - 한 번 null 검사를 하면 non-null임을 컴파일러가 알 수 있다
- null이 아닌 경우에만 호출되는 Safe Call (?.) 이 있다
- null인 경우에만 호출되는 Elvis 연산자 (?:) 가 있다
- null이 절대 아닐때 사용할 수 있는 널 아님 단언 (!!) 이 있다
- Kotlin에서 Java 코드를 사용할 때 플랫폼 타입 사용에 유의해야 한다
  - Java 코드를 읽으며 널 가능성 확인 
  - 자바 코드 사용 시 Kotlin으로 wrapping 하여 단일 지점으로 만든다.
