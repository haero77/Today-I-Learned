# RabbitMQ 개요

## RabbitMQ는 왜 나왔을까?

**RabbitMQ는 서비스 간 직접 호출에서 생기는 응답 대기, 장애 전파, 요청 폭주 문제를 해결하려고 나왔다.**

- **응답 대기**: 호출한 서비스의 작업이 끝날 때까지 기다려야 한다. 상대 서비스가 느리면 내 서비스도 느려진다.
- **장애 전파**: 호출한 서비스가 멈추면 요청이 실패한다. 이 실패가 내 서비스의 실패로 이어질 수 있다.
- **요청 폭주**: 요청이 한꺼번에 들어오면 상대 서비스에 그대로 전달된다. 처리량을 넘으면 응답이 느려지거나 서버가 멈출 수 있다.

RabbitMQ는 서비스 사이에서 메시지를 받아 준다. 받은 메시지는 Queue에 보관한다. 처리할 서비스는 Queue에서 메시지를 꺼내 작업한다.

```mermaid

    P["Producer<br/>주문 서비스"] --> R["RabbitMQ<br/>메시지 보관·전달"]
    R --> C["Consumer<br/>결제 서비스"]
```

## RabbitMQ는 왜 쓸까?

**RabbitMQ는 서비스를 분리하고 작업을 비동기로 처리하려고 쓴다.**

1. **기다리지 않아도 된다.**
   Producer는 메시지만 보내고 다음 일을 한다.

2. **장애가 바로 퍼지지 않는다.**
   Consumer가 멈춰도 메시지는 Queue에서 기다릴 수 있다.

3. **갑자기 몰린 요청을 받아 준다.**
   Queue에 요청을 쌓아 두고 처리할 수 있다.

4. **각자 처리할 수 있는 속도로 일한다.**
   Producer와 Consumer가 같은 속도로 움직일 필요가 없다.

> RabbitMQ는 메시지를 중간에 보관하고 전달한다. 덕분에 서비스는 서로의 속도와 장애에 덜 영향을 받는다.

## 개요

- [RabbitMQ](https://www.rabbitmq.com/)는 얼랭으로 만들어진 메시지 전송 브로커 오픈소스. (2007년 릴리즈)
- 시스템 간 비동기 메시징을 가능하게하여 서비스 간 통신을 안정적이고 효율적으로 처리할 수 있게 해줌.
- 플랫폼 중립적. 가볍고 다양한 언어들의 클라이언트 라이브러리를 제공.
- 유연한 성능과 안정성을 제공.
- 클러스터를 설정할 때 큐를 HA(High Available) 로 설정하여 여러 노드에 저장하므로서, 메시지 손실을 방지.
- 쉽게 새로운 기능 추가 가능.
- Federation 플러그인을 통해 데이터 동기화와 다중 마스터 복제를 구성 가능.
- 최근 MSA 환경에서 가장 일반적으로 쓰이는 기술중에 하나.
- 대량의 데이터 전송 시 발생할 수 있는 과부하를 분산시킴.
- 비동기 처리와 지연이 필요한 작업을 효과적으로 관리 가능.


## 대표적인 도메인 활용 사례

- EDA(Event-Driven Architecture):
  - 주문/결제/배송 등의 비즈니스 도메인을 이벤트 기반의 독립적인 도메인 모듈로 구성
- 로그 및 모니터링:
  - 로그 수집 및 준 실시간 처리 모니터링 시스템 구축
- 채팅 및 알람
- 비동기 데이터 처리:
  - 대용량의 이미지나 비디오 처리에 효율적인 분산 시스템 구축 가능
- 여러 디바이스의 요청 처리:
  - IoT와 같은 멀티 디바이스 환경에서의 요청 처리
