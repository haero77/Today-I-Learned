# 어댑터(Adapter)

어댑터는 **애플리케이션의 핵심 로직과 외부 세계를 연결하는 코드**다.

웹 요청, 데이터베이스와 같은 외부 기술은 애플리케이션과 사용하는 형식이 다르다. 어댑터는 둘 사이에서 요청과 데이터를 서로 이해할 수 있는 형태로 바꿔준다.

쉽게 말하면, 해외여행에서 사용하는 **돼지코(콘센트 변환 어댑터)**와 비슷하다.

- 애플리케이션의 핵심 로직을 외부 기술에 맞게 변경하지 않는다.
- 중간에 어댑터를 두어 서로 다른 연결 방식을 맞춘다.
- 덕분에 웹이나 데이터베이스 기술이 변경되어도 핵심 로직이 받는 영향을 줄일 수 있다.

## 어댑터의 두 종류

어댑터는 요청이 향하는 방향에 따라 인커밍 어댑터와 아웃고잉 어댑터로 나뉜다.

```text
외부 세계
   ↓
인커밍 어댑터
   ↓
애플리케이션
   ↓
아웃고잉 어댑터
   ↓
외부 세계
```

### 인커밍 어댑터

외부에서 들어온 요청을 받아 애플리케이션의 유스케이스를 호출한다.

예를 들어 `SendMoneyController`는 HTTP 요청을 애플리케이션이 이해할 수 있는 입력으로 바꾼 다음, 송금 유스케이스를 호출한다.

```text
HTTP 송금 요청
   → SendMoneyController
   → SendMoneyUseCase
   → SendMoneyService
```

여기서 `SendMoneyController`가 인커밍 어댑터다.

주요 역할은 다음과 같다.

- HTTP 요청을 받는다.
- 요청 값을 애플리케이션의 입력 모델로 변환한다.
- 알맞은 유스케이스를 호출한다.
- 실행 결과를 HTTP 응답으로 변환한다.

웹 컨트롤러뿐만 아니라 CLI 명령이나 메시지 큐의 메시지를 받아 유스케이스를 호출하는 코드도 인커밍 어댑터가 될 수 있다.

### 아웃고잉 어댑터

애플리케이션이 데이터베이스와 같은 외부 시스템을 사용해야 할 때 요청을 전달한다.

```text
SendMoneyService
   → AccountRepository
   → AccountRepositoryImpl
   → 데이터베이스
```

여기서 데이터베이스 접근 코드를 구현한 `AccountRepositoryImpl`이 아웃고잉 어댑터다.

주요 역할은 다음과 같다.

- 애플리케이션의 요청을 JPA나 SQL이 처리할 수 있는 형태로 변환한다.
- 데이터베이스에서 데이터를 조회하거나 저장한다.
- DB 엔티티와 도메인 객체를 서로 변환한다.

데이터베이스뿐만 아니라 외부 API, 파일 시스템, 이메일 발송 시스템 등에 연결하는 코드도 아웃고잉 어댑터가 될 수 있다.

## 포트와 어댑터의 차이

- **포트(Port)**: 애플리케이션이 외부와 소통하기 위해 정한 인터페이스
- **어댑터(Adapter)**: 포트를 실제 외부 기술에 연결하는 코드

예를 들어 애플리케이션이 계좌를 조회해야 한다면 다음과 같은 인터페이스를 정의할 수 있다.

```java
// 포트: 애플리케이션이 필요로 하는 기능을 정의한다.
interface AccountRepository {
    Account loadAccount(AccountId id);
}
```

영속성 어댑터는 이 인터페이스를 데이터베이스 기술로 구현한다.

```java
// 어댑터: 포트를 JPA나 SQL 같은 실제 기술에 연결한다.
class AccountRepositoryImpl implements AccountRepository {
    // 데이터베이스에서 계좌를 조회한다.
}
```

`AccountRepository`는 애플리케이션이 **무엇을 필요로 하는지** 정의하고, `AccountRepositoryImpl`은 그 일을 외부 기술을 이용해 **어떻게 수행할지** 구현한다.

## 핵심 정리

> 어댑터는 웹, 데이터베이스 같은 외부 기술과 애플리케이션의 핵심 로직 사이에서 요청과 데이터를 변환하고 연결한다.

어댑터를 사용하면 도메인과 유스케이스가 HTTP, JPA, SQL 같은 구체적인 기술을 직접 알 필요가 없다. 따라서 외부 기술이 변경되더라도 애플리케이션의 핵심 비즈니스 로직을 보호할 수 있다.
