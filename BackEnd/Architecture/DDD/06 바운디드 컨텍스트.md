# 바운디드 컨텍스트가 뭔가요?

- 바운디드 컨텍스트
  - (개념) **_여러 하위 도메인에 걸쳐 사용되어 불분명한 의미를 갖는 용어를, 분명한 의미를 갖게하는 경계._**
  - (구현) 특정 도메인 모델이 명확하고 완전한 의미를 갖도록 구분하는 경계

## 바운디드 컨텍스트는 왜 필요한가요?

- 바운디드 컨텍스트가 없으면, 한 개의 용어가 여러 의미로 쓰이게 되는 문제가 발생 가능하고, 그에 따라 모델이 모호해지고 복잡해져, 유지보수가 어려워짐.
  - 유지보수성이 떨어진다는 것은 기능 확장이 어렵고 개발 생산성이 떨어지는 것으로, 서비스 경쟁력이 떨어지게됨.

### 바운디드 컨텍스트 예시

- 온라인 서점을 예시로 들어, 책을 '상품'이라는 단어로 표현한다고 해봅시다.
- 그리고 이 회사에는 마케팅팀, 재고관리팀, 주문처리팀이 있고, 전부다 '상품'이라는 단어를 씁니다.
  - 상품 팀에서는 상품명, 상품 상세설명 등의 데이터가 필요할 거고,
  - 재고관리 팀에서는 재고 수량을,
  - 주문처리 팀에서는 주문 수량 등의 데이터가 필요할 겁니다.
- 그리고 이 요구사항을 하나의 모델에 다 넣는다고 해봅시다.

```java
// 😥 안티패턴: 모든 컨텍스트가 섞인 '만능 상품' 클래스
class Product {
    // --- 마케팅팀이 원하는 것 ---
    String name;
    String description;
    Money price;
    List<Image> images;
    List<Review> reviews;

    // --- 재고팀이 원하는 것 ---
    int stockQuantity;
    String warehouseLocation;
    String sku;

    // --- 주문팀이 원하는 것 ---
    int orderedQuantity;
    Money priceAtTimeOfOrder;
    Discount appliedDiscount;

    // ... 끝도 없이 늘어나는 필드들
}
```
- 그럼 Product라는 도메인 모델을 만들고, 여기에 모든 팀의 요구사항인 상품명, 상세설명, 재고 수량, 주문 수량 등등을 다 넣게 될 겁니다.
  - 그럼 이 Product 모델은 곧바로 너무 많은 책임과 데이터를 짊어지게 되고, 그 결과 유지보수성이 떨어지게 되겠죠.
- 예를 들어 재고팀에서 현재 재고 수량을 변경하는 로직을 수정한다고 해봅시다.
  - 재고 수량만 변경하는 로직을 건드리고 싶은데, 마케팅팀이나 주문팀의 요구사항이 같은 모델에 섞여있으니, 이 로직을 건드리다가 다른 팀 로직에 영향을 줄 수도 있겠죠.
  - 결국 영향도를 따지는 비용, 테스트 비용이 늘어나게 되고, 개발 생산성이 떨어지게 됩니다.
- 그래서, 컨텍스트를 나누고, 그에 맞는 도메인 모델을 구성한다~

## 바운디드 컨텍스트가 하는 일

- 특정 도메인 모델이 명확하고 완전한 의미를 갖도록 구분하는 경계.
- 바운디드컨텍스트는 사용자에게 기능을 제공하는 물리적 시스템으로, 도메인 모델은 이 BC안에서 도메인을 구현한다.

## 바운디드 컨텍스트의 범위 

- 표현, 응용, 도메인, 인프라 모든 영역을 포함
