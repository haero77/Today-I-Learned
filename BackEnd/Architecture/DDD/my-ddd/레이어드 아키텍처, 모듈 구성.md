## 레이어드 아키텍처가 뭔가요?

- 소프트웨어를, **서로 다른 역할을 가진 여러 개의 수평적인 계층**으로 나누어 구성하는 아키텍처.
- 레이어드 아키텍처가 갖는 의의는 관심사의 분리. 
  - 각 계층은, 자신만의 책임에만 집중하고, 다른 계층의 내부 동작은 신경 쓰지 않습니다.
- 핵심 규칙은 의존성이 상위 계층에서 하위 계층으로 한 방향으로만 흐르는 것
  - 각 계층의 독립성을 높여서 유지보수 용이. 각 부분 독립적으로 테스트 가능.
- 일반적으로 사용자와 직접 상호작용하는 표현(Presentation) 계층, 비즈니스 요구사항을 처리하는 비즈니스(Business) 계층, 데이터 영속화를 담당하는 데이터 접근(Data Access) 레이어 이렇게 3개의 레이어로 나누는 경우가 많습니다.

# DDD 레이어드 아키텍처 구성요소

| 계층      | 역할                                                                                                                                                       |
|---------|----------------------------------------------------------------------------------------------------------------------------------------------------------|
| 표현      | 사용자 요청을 받아 응용 영역에 전달. <br> 응용 영역 처리결과를 사용자에게 보여줌. <br> 웹 앱의 표현 영역은 HTTP 요청을 응용 영역에 전달 & 응용 영역의 응답을 HTTP 응답으로 변환 하여 전송                                    |
| 응용      | -  시스템이 사용자에게 제공해야할 기능을 구현.(예: 주문 등록, 주문 취소소, 상품 상세 조회) <br> - 응용 영역은 기능을 구현하기 위해 도메인 영역의 **도메인 모델을 사용.**       <br> - 로직을 직접 수행하기 보다는 도메인 모델에 로직 수행을 위임 |
| 도메인     | 도메인 영역은 도메인 모델을 구현, 도메인 모델은 도메인 핵심 로직을 구현.(예: '배송지 변경', '결제 완료') <br> Order, OrderLine, ShippingInfo ...                                                 |
| 인프라스트럭처 | 구현 기술에 대한 것을 다룬다<br>(예: RDBMS 연동 처리, 메시징 큐에 메시지 전송/수신, 몽고DB나 레디스와의 데이터 연동 처리, SMTP를 이용한 메일 발송 기능 구현, HTTP클라이언트를 이용해서 REST API호출)                         |



# 모듈, 패키지 구성

- 애그리거트, 모델, 리포지터리는 같은 패키지에 위치
- Order, OrderLine, Orderer, OrderRepository는 com.myshop.order.domain 패키지에 위치
- 도메인 복잡할 경우 도메인 모델과 도메인 서비스를 별도 패키지에 위치 가능
    - com.myshop.order.domain.order: 애그리거트
    - com.myshop.order.domain.service: 도메인 서비스
- 응용 서비스도 도메인 별로 패키지 구분 가능
    - com.myshop.order.application.product
    - com.myshop.order.application.category
